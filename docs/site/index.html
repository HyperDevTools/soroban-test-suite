01 / Quick start

Keep setup close to the test.

These helpers work with a Soroban SDK Env; your contract registration and client calls remain your test's responsibility.

use soroban_sdk::Env;
use soroban_test_suite::prelude::*;

#[test]
fn test_accounts_and_time() {
    let env = Env::default();
    let mut context = TestContext::new(&env);
    let users = context.create_accounts(2);
    assert_eq!(context.accounts().len(), 2);

    let clock = TimeController::new(&env);
    let before = clock.now();
    clock.advance(60);
    assert_eq!(clock.now(), before + 60);
    assert_ne!(users[0], users[1]);
}

Use the versions and feature flags declared by the repository's Cargo.toml. Run your contract tests with the normal Cargo test workflow.

02 / Toolkit

Three useful building blocks.

Each helper is deliberately test-scoped. The host SDK remains the source of truth for contract behavior and ledger semantics.

Fixture

TestContext

Create and retain generated addresses in one test context. Use BasicFixture when you need an admin address plus a set of users.

Clock

TimeController

Read, set, or advance the test ledger timestamp; next_ledger also advances sequence and timestamp for time-dependent paths.

Budget

GasTracker

Capture CPU instruction and memory usage around a measured section. Its start/stop lifecycle returns errors, so handle those results in your tests.

03 / Read before relying

Know what is implemented.

Some older README examples describe planned helpers rather than the current library surface. Check the source before building a test around an API.

MockContract is not a working mock framework yet.

The current MockContract is a placeholder. Contract registration, token-balance/event/storage assertions, and snapshot testing are not provided by the current implementation. This crate is for local testing, not production transaction signing or key management.

See the actual source modules, open issues for planned work, or read the official Soroban documentation for SDK and ledger behavior.
